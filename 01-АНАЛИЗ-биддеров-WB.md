## Часть 1. Официальный API Wildberries для рекламы (advert-api)

Источники: официальная спека «Маркетинг и продвижение» https://dev.wildberries.ru/docs/openapi/promotion (за антиботом 498 для скриптов) — проверено по верифицированному зеркалу OpenAPI-спеки, снимок **2026-09-26**: https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/clients/go/promotion/api/openapi.yaml (репозиторий-генератор клиентов: https://github.com/eslazarev/wildberries-sdk, спеки обновляются автоматически из S3 WB).

Хост продакшена: **advert-api.wildberries.ru**, песочница: advert-api-sandbox.wildberries.ru.

### 1.1 Что подтверждено в актуальной спеке (снимок сентябрь 2026)

**Списки и информация о кампаниях**
- `GET /adv/v1/promotion/count` — списки всех кампаний по типу и статусу. Лимит 5 req/s (Personal/Service).
- `GET /api/advert/v2/adverts` — информация о кампаниях (ids ≤ 50). Статусы: -1 удалена, 4 готова к запуску, 7 завершена, 8 отменена, 9 активна, 11 на паузе. Модели оплаты: `cpm` (за показы) и `cpc` (за клики). Тип управления ставкой: `bid_type: manual | unified`. Ставки — `bids_kopecks: {search, recommendations}` (копейки). Лимит 5/s (Базовый токен — 1 req/час!).

**Управление кампанией**
- `GET /adv/v0/start` (запуск), `GET /adv/v0/pause` (пауза), `GET /adv/v0/stop` (завершение), `GET /adv/v0/delete`, `POST /adv/v0/rename`.
- Создание кампании: `POST /adv/v2/seacat/save-ad` (ручная ставка поиск/рекомендации или единая ставка). Лимит 5/мин.
- Добавление/удаление карточек: `PATCH /adv/v0/auction/nms` (статусы 4/9/11). Добавляемым товарам ставится текущая минимальная ставка. Лимит **1 req/s**.
- Смена мест размещения (поиск/рекомендации) для ручных CPM: `PUT /adv/v0/auction/placements`. Лимит **1 req/s**.

**Ставки — ядро биддера**
- `PATCH /api/advert/v1/bids` — смена ставок по артикулам. Тело: `bids:[{advert_id, nm_bids:[{nm_id, bid_kopecks, placement}]}]`, placement = `combined` (единая) | `search` | `recommendations` (ручная). Лимит **5 req/s**.
- `POST /api/advert/v1/bids/min` — минимальные ставки по товарам (пример: combined 155 коп., search 250 коп.). Лимит 20/мин.
- `GET /api/advert/v0/bids/recommendations` — **рекомендуемые ставки** (фактический аналог «аукциона» в API): для CPM — `base{competitiveBid, leadersBid}`, по поисковым кластерам `normQueries[{normQuery, reachMax{bidKopecks, bidKopecksMin}, reachMedium, reachMin}]`; для CPC — уровни позиций `levels{range1To2, range3To10, range11To34}` (пример: 1–2 место 21,38 ₽; 3–10 — 8,30 ₽; 11–34 — 6,28 ₽ за клик). Лимит 5/мин.
- Ставки на поисковые кластеры (ключевые фразы): `POST /api/advert/v1/normquery/bids` (**только Personal/Service токен**), `POST /adv/v0/normquery/bids` (в копейках), `POST /adv/v0/normquery/get-bids`, `POST /adv/v0/normquery/list`, статистика кластеров `POST /adv/v0/normquery/stats` и `POST /adv/v1/normquery/stats` (по дням).
- **Минус-фразы автоматизируются**: `POST /adv/v0/normquery/set-minus` («устанавливает и удаляет минус-фразы в кампаниях с единой и ручной ставкой», пустой массив = удалить все), `POST /adv/v0/normquery/get-minus`.
- Шаги ставок и валюту аккаунта: `GET /api/advert/v1/config` (пример из спеки: `cpcStep: 500, cpmStep: 100000` — но пример в UZS, в рубли переносить нельзя; для RU-аккаунта значения спрашивать у живого API). Только Personal/Service.
- Дневные лимиты CPC-кампаний: `GET / PUT /api/advert/v0/daily-limits` (включить/выключить/обновить суточный максимум). Только Personal/Service, 5/мин.

**Статистика**
- `GET /adv/v3/fullstats` — полная статистика любых кампаний, период ≤ 31 день. Метрики: views, clicks, ctr, cpc, cr, atbs (корзины), orders, shks (выкупы), sum (выручка по рекламе), sum_price, canceled; разбивка по дням × платформам × товарам; `boosterStats[].avg_position` (средняя позиция!). Лимит **жёсткий: 3 req/мин**.
- Статистика медиакампаний: `POST /adv/v1/stats`, `GET /adv/v1/count|adverts|advert`.
- НО: устаревшие `/adv/v1/fullstat`, `/adv/v2/fullstat`, `/adv/v1/auto/statistics`, `/adv/v0/promotion/adverts` в актуальной спеке отсутствуют.

**Финансы**
- `GET /adv/v1/balance` — общий рекламный баланс. 1/s.
- `POST /api/advert/v2/budget` — остатки бюджетов кампаний (20/мин). Заменил deprecated `GET /adv/v1/budget` («метод будет отключен 16 ноября» — релиз-ноты WB id=582).
- `POST /adv/v1/budget/deposit` — **пополнение бюджета кампании через API возможно** (1/s).
- История затрат `GET /adv/v1/upd`, пополнений `GET /adv/v1/payments`.
- Календарь акций: `GET /api/v1/calendar/promotions` (+details, nomenclatures, upload).

**Синхронизация данных WB** (из шапки спеки): данные обновляются **раз в 3 минуты**, статусы кампаний — раз в минуту, **ставки — раз в 30 секунд**. Значит опрашивать чаще бессмысленно.

### 1.2 Чего в API НЕТ (проверено grep по всей спеке от 2026-09-26)

- **`/adv/v1/search/auction/placements`, `/adv/v1/search/auction/bid`, `/adv/v1/auto/auction` — НЕ ПОДТВЕРЖДЕНЫ.** Нет в спеке, ни в одном найденном враппере, ни в поиске. Снапшот «аукциона» целиком недоступен — «состояние аукциона» биддер видит только через `bids/recommendations` (конкурентная ставка / ставка лидеров / уровни охвата) и `fullstats` (avg_position). Если кто-то из сервисов заявляет «реальные ставки каждые N минут» — вероятно, это и есть `bids/recommendations`, либо неофициальный канал (запрещён офертой).
- **Расписание показов по часам — методов нет** (0 вхождений «schedule»). Все сервисы (PromoPult, Sellego, MPSTATS «Ставка по времени», MP Manager) делают это **паузой/стартом кампаний** по расписанию — `GET /adv/v0/pause|start`.
- Транзит бюджета между кампаниями: метода вывода нет, только `budget/deposit` (пополнение).
- Управление старыми авторекламами (`/adv/v1/auto/*` — исключения фраз, updatenm) из API убрано; ставки сейчас меняются общим `PATCH /api/advert/v1/bids` (единая ставка).

### 1.3 Токены, лимиты, законность

- Тип токена: **Personal** (личный), категория **«Продвижение»** — покрывает все методы выше; на запись в 4 методах (normquery/bids, config, daily-limits) нужен Personal/Service. Лимиты — token bucket по методу и типу токена, 429 с заголовками `X-Ratelimit-Retry/Limit/Reset`. Один 4XX-запрос в категории Marketplace стоит ×10 — аккуратнее с ошибками.
- Токен живёт 180 дней, показывается один раз. При этом MPSTATS рекомендует своим клиентам менять токен «каждые 10 дней» (wiki) — это практика сервиса, требование WB не подтверждено.
- **Оферта WB п. 9.10** (с 05.2023): запрещены сторонние «серые» API и интеграция с кабинетом в обход официального API (п. 9.9.6) — санкция блокировка. Биддер обязан работать строго через advert-api с токеном продавца.
- **Платный доступ к WB API** для облачных сервисов из Каталога решений (новость WB от 23.10.2025, действует с 01.01.2026): модель pay-as-you-go для сервисов, продающих доступ третьим лицам. **Для продавца со своими скриптами на своих токенах API заявлен бесплатным** (точные цены прайс-листа не подтверждены — за антиботом). Вывод: для «свои кабинеты» — ок; если когда-нибудь будем продавать биддер как SaaS чужим селлерам — потребуется регистрация в Каталоге решений и Service-токены.

### Ключевые детали по каждому (источники — офиц. сайты/вики/доки)

**MPSTATS** (wiki.mpstats.io — база знаний открытая):
- Работает только с уже созданными на WB кампаниями, через официальный API-токен «Продвижение + Аналитика», уровень «чтение и запись».
- Ставка каждые 3 мин; фразы обновляются раз в час; задержки статистики со стороны WB «до 15 минут» (в другом разделе — «до 2 часов» для обновления по API).
- «Ставка по времени»: до 9 временных диапазонов со своей ставкой, вне диапазона — пауза кампании; тепловая карта заказов для подбора часов.
- Автоминусация кластеров по условиям (CTR, показы, частота), проверка раз в час; «контроль органики» — кластер в минус, если товар уже стоит в органике по нему (проверка раз в 2 ч). Лимит WB: **1000 минус-кластеров на товар**.
- Дневной лимит минимум 100 ₽, проверка раз в 10 мин (погрешность 50–100 ₽ — списание успевает уйти), автозапуск в 00:00 МСК.
- Атрибуция заказов WB — 7 дней; данные уточняются задним числом повторными запросами.
- Известные ограничения самих MPSTATS: не все позиции достижимы (WB отдаёт часть мест органике), выдача в приложении ≠ выдаче сайта, два автобиддера одновременно конфликтуют, вне «приоритетного предмета» целевое место недостижимо.
- Тарифы: Базовый 50 РК / Бизнес 90 / Корпоративный 300 под биддером; докупка 5 000 ₽ за 100 РК. Рублёвые цены на офиц. странице не извлекаются (JS) — сторонние оценки 3 360–4 800 ₽/мес считать неподтверждёнными.

**Маяк**: токен типа «Реклама»; заявляет, что токен даёт только чтение — но тогда механика «перебить на +1 ₽» работает не через официальный API (на сайте описано подключение и через браузерное расширение) — противоречие отмечено, детали не раскрыты. Отзывы (otzovik, 4.0/227): расхождения расходов с кабинетом «в 2 раза», подписка навязывается на 24 мес без возврата.

**MP Manager**: единственный с KPI-стратегиями (Автопилот «удерживать CPC/ДРР/конверсию, а не позицию»; Воронка — целевые CPM/CPC/стоимость корзины/заказа/ДРР; Конверсии — максимизировать клики/корзины в рамках бюджета). Правила по остаткам, оборачиваемости, заказам. Алерты: бюджет закончился, автопополнение сработало, РК на паузе, нет показов по ключам, появились новые фразы. Свой публичный REST API (api.mpmgr.ru). Официальные документы: mpmgr.ru/docs.

**Sellego**: автоставки и удержание позиций по кластерам с учётом гео, автоминусация, белые списки фраз, импорт фраз из «Джема» (Джем — аналитическая подписка WB), Telegram-уведомления, контроль органики, ассоциированные конверсии.

**PromoPult**: биддер бесплатен, механика открыто описана (blog.promopult.ru — инструкция с картинками): единая ставка (CPM не меньше 120 ₽), биддер поисковых кластеров (отдельные ставки: с продажами / с интересом / без сигнала спроса + дефолтная), недостижимая позиция → макс. ставка / пауза с возобновлением / стоп, логи всех изменений ставок, AI-подсказки по мастер-фразам. Подключение: API-ключ или oAuth WB (один проект на селлера).

**Orkestro**: сайт не резолвится с 2026 (lame delegation). Архив: Free 3 РК / 3980 / 9750 ₽, автопополнение, «+1 ₽ выше конкурента», не ставит ниже минимума и дробные, анти-самоконкуренция. Использовать как референс.

**Moneyplace**: закрыт с 01.11.2025 (оферта на сайте; выкуплен СКБ Контур в 03.2025). Тарифы на момент закрытия: Premium 9 900 / Deluxe 13 900 / Enterprise 55 000 ₽/мес.

**Market Papa**: сейчас бесплатный Chrome-плагин (60k пользователей) — кластеры и пресеты фраз в авторекламе, актуальная ставка для позиции, ставки конкурентов, позиции за последний час. Биддера нет.

### Общая архитектура всех биддеров (она одинаковая)

1. **Сборщик** по токену «Продвижение»: кампании (`promotion/count`, `adverts`), ставки конкурентов (`bids/recommendations`), остатки бюджетов (`budget`), статистика (`fullstats`), мин. ставки (`bids/min`). Дополнительно токены «Аналитика» (воронка, поисковые запросы) и «Статистика» (заказы/выкупы) для ДРР и воронки.
2. **Хранилище истории**: ставки, позиции, показы/клики/заказы по товарам/кластерам/дням — без истории ставки «до/после» бесполезны.
3. **Движок стратегий**: целевая позиция + макс. ставка; удержание; по времени; KPI (ДРР/CPC/CPO); биддер по кластерам.
4. **Исполнитель** с rate-limiter: `PATCH bids` (5/s), `pause/start` (расписание), `daily-limits`, `set-minus`, `budget/deposit`. Все действия логируются (PromoPult и MP Manager подчёркивают «лог всех изменений»).
5. **Защита бюджета**: дневной лимит (CPC — нативно через API; CPM — мониторингом расхода и паузой), автопополнение по порогу, алерты.
6. **Уведомления**: Telegram (Marpla 4 бота, Sellego, MP Manager).
7. **Веб-кабинет**: дашборды, тепловая карта часов, трекер позиций.

Физические ограничения, общие для всех (независимо от сервиса):
- Данные WB синхронны с задержкой: ставки 30 с, статусы 1 мин, статистика 3+ мин (по опыту MPSTATS — до 15 мин и дольше, с ретроспективными уточнениями).
- Атрибуция заказов к клику — 7 дней, данные «доезжают» задним числом → любое KPI-правило по ДРР/заказам должно учитывать окно атрибуции.
- `fullstats` — 3 req/мин: при 50 кампаниях полный цикл сбора ≥ 17 минут; это предел частоты KPI-решений «по всем кампаниям сразу».
- Часть позиций выдачи занята органикой и недостижима рекламой.

## Часть 3. Что уже есть готового (MCP / скилы / SDK / биддеры)

- **wb-mcp-server** (github.com/DeviceIngineering/wb-mcp-server, PyPI, v2.6.1 от 05.09.2026, MIT): 202 инструмента по Seller API, из них 22 рекламных — list/create/pause/start/stop, stats, **bids_set, bids_recommendations, cluster_bids**, минус-фразы, balance/budget/deposit. Multi-account по `shop_id`. Чего нет: снапшота аукциона и **логики биддинга** — это ручные инструменты. Годится как основа/референс адаптера.
- **RTHeLL/wbsdk** (Python, MIT, обновлён 08.2026): модуль Promotion — кампании, ставки, бюджет, fullstats, normquery, per-domain rate limiting, retry 429. Лучший SDK-фундамент.
- **ilyautov/marketplaces-mcp-ru** (44★, alpha): 1022 метода из спеков, safety-гейты; HTTP-глаголы из спеков могут не совпадать с реальными — осторожно.
- **MissiaL/wildberries-api** (agent-skill, MIT, снапшот 03.10.2026): 307 операций из 13 офиц. спеков, retry по X-Ratelimit — скил-вариант для агентов.
- **Готовые биддеры**: все найденные open-source мертвы (свежайший — ogroshev/wb-advert-auto-bid, коммит 06.2023, использует убитые эндпоинты `/adv/v0/cpm` и скрейпинг). Логика «аукцион → решение → ставка» на актуальном API никем открыто не реализована.

**Вывод:** брать готовый биддер неоткуда; фундамент — свой сервис. Переиспользуем: паттерны wb-mcp-server (адаптер, rate-limit, multi-account), wbsdk как референс клиента.

## Часть 4. ТЗ-скелет нашего биддера (по требованиям из задачи)

Требования пользователя → чем закрывается:
1. «Платили меньше, получали больше заказов» → стратегии: (а) удеражание минимально достаточной ставки по `bids/recommendations` (competitiveBid/reachMin — не платить больше входа в целевой диапазон охвата); (б) KPI-стоп/снижение по ДРР/CPA из `fullstats` + воронки с учётом 7-дневной атрибуции; (в) минус-фразы нерелевантных кластеров по `normquery/stats` + `set-minus`.
2. «Показ только в активные часы покупателей» → сетка часов из тепловой карты заказов (наша статистика sales по `statistics-api` / воронка `seller-analytics`) + исполнитель `pause`/`start` по расписанию (лимит 1 req/s, для десятков кампаний — очередь с разбросом по минуте).
3. «Анализ выдачи, конкурентов, статистики → подсказки, какие товары в рекламу» → периодический отчёт: товары с хорошей органикой/конверсией без рекламы + кластеры с высоким спросом (`analytics` поисковые запросы) + ставки входа (`bids/recommendations`) + юнит-экономика (есть наша!) → рекомендация «товар X, кластер Y, ставка входа Z ₽, прогноз».

Обязательные подсистемы: rate-limiter на токен (глобальный планировщик, приоритет: расписания > ставки > сбор статистики), хранение истории ставок/выдачи, журнал всех действий с откатом-пониманием «почему изменили», стоп-предохранители (макс. ставка, макс. расход/день, kill-switch), Telegram-уведомления, веб-кабинет.

Ограничения, которые надо принять в дизайне:
- Расписание показов = пауза/старт, не «часы показов» платформы.
- KPI-решения по всем кампаниям разом — не чаще ~раз в 15–20 мин (3 req/мин на fullstats).
- Данные уточняются ретроспективно → все решения по окнам атрибуции, пересчёт назад.
- Не все позиции достижимы; приложение ≠ сайт.
- Токены: Personal, категории «Продвижение» + «Аналитика» + «Статистика» (+«Цены и скидки»/контент позже, для связи с юнит-экономикой). Двух биддеров на один кабинет одновременно быть не должно (конфликт ставок).

## Часть 5. План действий (поэтапно, до кода — только скоуп)

**Этап 0. Доступы и сверка (1–2 дня)**
1. Создать Personal-токены в каждом кабинете (Продвижение, Аналитика, Статистика).
2. Живой прогон по спеке от 26.09.2026: подтвердить реальные пути/поля (спека-зеркало ≠ гарантия), снять значения `config` (шаги ставок RU-аккаунта), `bids/min`, проверить отдаёт ли `fullstats` avg_position в 2026.
3. Зафиксировать тарифный план WB API для наших сценариев (свои токены = бесплатно, перепроверить новость pay-as-you-go).

**Этап 1. Сборщик + хранилище (неделя 1–2)**
- Воркер-сборщик: кампании, ставки, бюджеты, баланс, fullstats (кольцевой буфер по лимиту 3/мин), min-ставки, recommendations — в Postgres.
- Таблицы: campaigns, bids_history, stats_daily/hourly, clusters (normquery), budget_log. Тот же хостинг, что отзывы/юнитэкономика (стек уточняется).

**Этап 2. Дашборд мониторинга (неделя 2–3)**
- Веб: все кабинеты, РК, ДРР/CPC/CTR/заказы, расход против бюджета, история ставок и позиций. Только чтение — без рисков.

**Этап 3. Контроллер бюджетов и расписаний (неделя 3–4)**
- Суточное расписание (пауза/старт по часам из тепловой карты заказов), дневной лимит с автостопом/автозапуском, автопополнение по порогу (аккуратно — это деньги), Telegram-алерты, kill-switch.

**Этап 4. Биддер (неделя 4–7)**
- Стратегии MVP: «Удержание ставки» (фикс CPM), «Мин. вход» (ставка = reachMin/competitiveBid + шаг, не выше максимума), «Целевой диапазон» (по recommendations-уровням CPC). Частота 1–3 мин (выше нет смысла — WB обновляет ставки раз в 30 с, у конкурентов лимиты API).
- Режим «тень» первые 1–2 недели: считает решения, пишет в журнал, НЕ применяет. Сверка с человеком → переводим кампании на авто.
- Анти-самоконкуренция: запрещаем перебивать свои же кампании по одному кластеру/товару.

**Этап 5. Минус-фразы (неделя 7–8)**
- Правила: CTR < порога при N показах → в минус; «контроль органики» (товар в топ-3 органики → кластер в минус); белые списки. Лимит WB 1000/товар.

**Этап 6. Рекомендатор «что в рекламу» (неделя 8–10)**
- Связка: поисковые запросы (analytics) + наша воронка/выкупы + юнит-экономика (маржинальность есть в нашем учёте) + ставки входа → отчёт-подсказки в веб и Telegram. Без автозапуска кампаний (создание РК — ручное, подтверждённое).

**Параллельно:** регистрация не нужна (не SaaS); если когда-то продаём доступ — Каталог решений WB + Service-токены + платный API.

## Часть 6. Не подтверждено / открытые вопросы

1. **Какой хостинг и стек у «отзывов» и «юнитэкономики»** — в локальных проектах однозначно не нашёл. Нужно от пользователя: сервер, ОС, рантайм, БД, домены.
2. Точные цены MPSTATS в рублях (офиц. страница JS) и текущий прайс платного WB API для сервисов (новость за антиботом).
3. «Реальные ставки каждые N минут» у части сервисов (Маяк, XWAY) — через что они их берут: `bids/recommendations` или неофициальный канал — не подтверждено. Наш путь — только официальный.
4. Поведение `boosterStats.avg_position` в fullstats в 2026 (форумное сообщение о его отключении с 03.07.2026 — не проверено без боевого токена).
5. Сохранится ли формат «аукциона» (CPM за кластеры охвата) — WB меняет рекламу 2–3 раза в год (2024: аукцион в поиске; 2025: CPM-автокампании; 09.2026: `/api/advert/v2/*` заменяет `/adv/v1/budget`) → архитектура должна переживать замену эндпоинтов.
