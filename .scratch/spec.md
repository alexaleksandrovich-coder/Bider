# Спек: Bider подпроект №1 — спайк + сборщик + дашборд (read-only)

Дата: 2026-10-11. Статус: на ревью владельца.
Основа: исследование [01-АНАЛИЗ-биддеров-WB.md](../01-АНАЛИЗ-биддеров-WB.md) (офиц. спека advert-api, снимок 26.09.2026).

## Problem Statement

Реклама в 4 кабинетах Wildberries (3 Belarus/BYN + 1 Россия/RUB) крутится вслепую: расход, ставки, позиции и эффективность видно только поштучно в кабинетах WB, история ставок не сохраняется, решения о ставках принимаются без данных. Прежде чем строить автобиддер (фазы 2+), нужен фундамент: надёжный сбор данных по официальному API и дашборд только для чтения.

## Solution

Один FastAPI-сервис «bider» на том же сервере, что answers.robotay.ru: встроенные фоновые asyncio-циклы собирают по каждому кабинету кампании, ставки, бюджеты, балансы, статистику и снапшоты аукциона в PostgreSQL; веб-дашборд за логином показывает расход, ДРР, историю ставок и позиций по всем кабинетам. В фазе 1 сервис НИЧЕГО не пишет в WB — только читает.

## User Stories

1. Как владелец, я хочу подключить кабинет WB по Personal-токену, чтобы видеть его рекламу в общем дашборде.
2. Как владелец, я хочу на обзорной странице видеть по каждому кабинету расход за сегодня/7/30 дней и рекламный баланс, чтобы контролировать деньги без входа в кабинеты WB.
3. Как владелец, я хочу видеть список всех РК кабинета (тип, статус, модель оплаты, текущая ставка по поиску/рекомендациям), чтобы быстро находить проблемные кампании.
4. Как владелец, я хочу по каждой РК видеть показы, клики, CTR, CPC, корзины, заказы, выкупы, выручку и ДРР за выбранный период (7/30 дней), чтобы оценивать эффективность.
5. Как владелец, я хочу график изменения ставок по товарам РК во времени, чтобы видеть динамику аукциона.
6. Как владелец, я хочу график средней позиции (avg_position из boosterStats), чтобы замечать просадку видимости.
7. Как владелец, я хочу для CPC-РК видеть дневной лимит и остаток бюджета кампании, чтобы замечать сливы.
8. Как владелец, я хочу для аукционных РК видеть кластеры/фразы с их статистикой, чтобы понимать, за что плачу.
9. Как владелец, я хочу сводку по товарам (nmID) через все РК: расход vs выручка, чтобы видеть, какой товар сколько съедает рекламы.
10. Как владелец, я хочу вход по логину/паролю с сессиями в БД, чтобы посторонние не видели рекламные расходы.
11. Как владелец, я хочу страницу health со свежестью данных по каждому циклу сбора и журналом ошибок, чтобы понимать, данным можно доверять или нет.
12. Как владелец, я хочу, чтобы после простоя сервера сбор сам «догонял» пропущенные периоды (fullstats умеет окна до 31 дня), чтобы история не рвалась.
13. Как владелец, я хочу, чтобы токены хранились зашифрованными (Fernet, ключ в .env вне репо), чтобы утечка БД не отдавала кабинеты.
14. Как владелец, я хочу видеть суммы в валюте кабинета (BYN/RUB) с правильным масштабом, чтобы не путать копейки с рублями.
15. Как владелец, я хочу спайк-отчёт по живому API до написания сборщика, чтобы факты (работают ли BY-токены, валюта, шаги ставок, реальные поля ответов) были зафиксированы, а не взяты из спеки.
16. Как владелец, я хочу, чтобы сборщик уважал лимиты WB (в т.ч. fullstats 3 req/мин) и обрабатывал 429 по заголовкам X-Ratelimit, чтобы WB не заблокировал токены.
17. Как владелец, я хочу первые 2 недели сырые ответы API в журнале (retention 14 дней), чтобы отлаживать реальные форматы.
18. Как владелец, я хочу тесты на рейт-лимитер, парсеры и запись данных, чтобы сборщик не молча портил историю.
19. Как владелец, я хочу график расходов по дням на странице РК, чтобы видеть тренд, а только не сумму.

## Implementation Decisions

- **Один процесс**: FastAPI-приложение + встроенные asyncio-циклы сбора (подход «A»). Рестарт веба = пауза сбора на пару минут, догон задних окон сам.
- **Стек**: Python 3.12+, FastAPI, SQLAlchemy 2 + Alembic, PostgreSQL 16, httpx (async), Jinja2 + HTMX, pytest + pytest-asyncio + respx, uv, ruff. Подробно: [stack.md](stack.md).
- **Спайк до кода сборщика**: `scripts/spike_probe.py` гоняет read-методы по 1 BY и 1 RU токену, пишет `.scratch/facts.md`: живые хосты/пути, валюта и масштаб ставок из `/api/advert/v1/config`, реальные типы РК, наличие avg_position в fullstats, реальные лимитные заголовки. Константы сборщика (`app/wb/constants.py`) заполняются ТОЛЬКО из facts.md.
- **Циклы сбора** (частоты из анализа, правятся после спайка):
  - `campaigns` — promotion/count (5/с) + /api/advert/v2/adverts пакетами ≤50 (5/с): каждые 5 мин.
  - `budgets` — /api/advert/v2/budget (20/мин): каждые 5 мин.
  - `balance` — /adv/v1/balance (1/с): каждые 5 мин.
  - `fullstats` — /adv/v3/fullstats (3/мин): кольцевой обход РК; окно «сегодня» на РК каждые ~20 мин; скользящее ретро-окно 7 дней на РК раз в сутки (уточнение атрибуции задним числом).
  - `bids_min` — /api/advert/v1/bids/min (20/мин): раз в сутки.
  - `auction_snapshot` — /api/advert/v0/bids/recommendations (5/мин): каждые 60 мин по активным РК (сырой jsonb + распарсенные competitive/leaders/reach).
  - `clusters` — /adv/v0/normquery/list + /adv/v1/normquery/stats: раз в сутки для РК с ручной ставкой.
- **Рейт-лимитер**: AsyncTokenBucket на пару (cabinet, класс методов), часы/sleep инъектируются для тестов; 429 → сон X-Ratelimit-Retry (или экспоненциальный бэкофф с джиттером), 3 подряд ошибки цикла → пауза цикла 15 мин + запись в collection_log.
- **Read-only**: только методы чтения офиц. advert-api. Никаких PATCH/PUT/PATCH-bids, pause/start, deposit. Host только advert-api.wildberries.ru (оферта WB п. 9.10 запрещает неофиц. API).
- **Модель данных** (Postgres, схема `bider`):
  - `users(id, username unique, password_hash, created_at)`, `sessions(token pk, user_id, expires_at)`
  - `cabinets(id, name, wb_type 'BY'|'RU', currency, token_encrypted, active, created_at)`
  - `campaigns(cabinet_id, advert_id, name, type, status, payment_type, bid_type, placement_search bool, placement_reco bool, change_time, updated_at, pk(cabinet_id, advert_id))`
  - `bid_history(id bigserial, cabinet_id, advert_id, nm_id, placement, bid_kopecks bigint, captured_at)` — append-only
  - `stats(cabinet_id, advert_id, nm_id, date, app_type, views, clicks, atbs, orders, shks, sum_price_kopecks, sum_kopecks, cpc_kopecks, canceled, pk(все ключи))` — upsert из days[] fullstats
  - `positions(cabinet_id, advert_id, nm_id, date, avg_position numeric, pk)` — из boosterStats
  - `budgets(cabinet_id, advert_id, cash_kopecks, netting_kopecks, total_kopecks, captured_at)`
  - `balances(cabinet_id, total_kopecks, captured_at)`
  - `auction_snapshots(id, cabinet_id, advert_id, captured_at, payload jsonb, parsed jsonb)`
  - `clusters(cabinet_id, advert_id, norm_query, plus_type, stats jsonb, bid_kopecks, updated_at)`
  - `collection_log(id, cabinet_id, loop_name, status, detail, started_at, finished_at)`
  - `raw_responses(id, cabinet_id, endpoint, status, payload jsonb, captured_at)` — retention 14 дней, чистка nightly
- **Деньги**: везде integer в копейках базовой валюты кабинета; форматирование на фронте по `currency` (BYN/RUB, 2 знака). ДРР = sum/sum_price, считается при выводе.
- **Auth**: логин/пароль, scrypt (hashlib.scrypt, salt), сессии в БД (httpOnly cookie, срок 30 дней), seed-админ из `.env` при первом старте.
- **Страницы**: `/login`; `/` — обзор 4 кабинетов (расход сегодня/7/30, баланс, алармы свежести); `/cabinets/{id}` — список РК + фильтр по статусу; `/cabinets/{id}/campaigns/{advertId}?days=7|30` — детальная РК (метрики, графики ставок и позиций, бюджеты/лимиты, кластеры); `/items?cabinet={id}` — сводка по товарам; `/health` — свежесть циклов + журнал; статика: HTMX + Chart.js локально из `app/static/vendor`.
- **Деплой**: VM answers.robotay.ru, uvicorn-сервис за Caddy (способ юнита — как у answers: systemd или docker, уточняется владельцем), Postgres на той же VM, база `bider`, миграции Alembic при деплое.
- **Часовой пояс**: данные WB — Москва UTC+3; в БД даты как date (по МСК), captured_at — UTC.

## Testing Decisions

- Хороший тест = проверяет внешнее поведение, не внутренности: лимитер — «N вызовов не быстрее rate», парсер — «фикстура ответа → точные строки», репозиторий — «двойная запись идемпотентна», цикл — «по расписанию с фейковым временем».
- Unit: лимитер (математика bucket, сон при 429), парсеры fullstats/adverts/budget/recommendations (фикстуры — реальные ответы из спайка), формат денег/ДРР.
- Integration: репозитории и миграции на реальном Postgres из docker-compose.dev; сборщик с фейковым WB-клиентом и фейковыми часами; веб — FastAPI TestClient (редиректы без логина, 200 с сидом, логаут).
- Приоритет покрытия: лимитер, парсеры, запись данных, догон окон — 100% веток; шаблоны — smoke.
- Prior art по стилю: тесты accountant-sellers-by (изолированные, быстрые, без сети); сеть всегда мокается (respx), живой API трогает только спайк-скрипт.

## Out of Scope (фаза 1)

- Любые записи в WB: ставки, пауза/старт, бюджеты, депозиты, минус-фразы (фазы 2–5).
- Рекомендатор «что в рекламу», Telegram-уведомления, роли/мультипользовательность, экспорт CSV, тёмная тема.
- Аналитика продаж/воронки вне рекламной статистики (orders/shks из fullstats достаточно для фазы 1).
- Подключение чужих кабинетов (только наши 4).
